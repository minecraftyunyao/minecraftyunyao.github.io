狼人行动改图基础一

|总字数:2.6k|阅读时长:7分钟|浏览量:

Hello，各位读者，我们又见面了！

今天这篇教程将继续承接上一篇文章的内容,带大家把路线一完整走完。
老规矩，文章声明依然有效，不再赘述。

开始

本篇将为你彻底扫清以下困惑：

· 诸神黄昏 怎么实现？身份如何添加？
· 地图数量那么多，随机地图 的机制该怎么做？
· 想塞入多种游戏模式，随机模式 又该如何设计？

地图机制逻辑讲解

在动手改图之前，我们先来简单拆解一下这张地图的底层运行逻辑。

第一部分 地图的核心驱动装置

来到地图的原指令区，你会看到一套整齐的装置，如下图所示：

两套循环命令方块，再加上命令方块矿车，共同构成了整张地图的核心驱动。

  • function moment 循环命令方块，每 1 个游戏刻（即 1/20 秒 = 50 毫秒）执行一次，负责高频计时、实体清理等需要即时响应的任务。
  • function second 循环命令方块，每秒执行一次（通过 moment 累加 tempb 达到 20 来触发），负责倒计时刷新、技能窗口倒计时等低频但稳定的逻辑。
  • 核心计时命令执行实体: 命令方块矿车[command_block_minecart],整个地图的命令是根据命令方块矿车为执行者，这也就是为什么在第一章中强调保护命令方块矿车，严禁使用/kill @e指令。
    作用:
  1. 全局计数器：存储 temp、tempb、tempc 三个计分板变量，作为全局可访问的数据容器。
  2. 计时基准：function moment 每刻执行 scoreboard players add @e[type=command_block_minecart] tempb 1，tempb 累加到20时触发 function second。
  3. 人数统计：execute @a ~~~ scoreboard players add @e[type=command_block_minecart] temp 1，temp 值等于当前玩家总数，身份分配指令以 scores={temp=6..} 为前置条件。
  4. 数值中转：通过 scoreboard players operation @e[type=command_block_minecart] temp = GAMEOVER show 将虚拟实体的数值复制到矿车，供 @e 选择器匹配。
  5. 状态门闩：修改矿车的 temp 或 tempb 数值，控制指令执行区间（如 tempb=0..199），防止指令重复触发。
  6. 不被清理：被实体清理白名单（type=!command_block_minecart）排除，永不消失，保证数据持久化。
    以上只是博主的研究猜测,对于改图没实际意义，了解即可。

第二部分 游戏逻辑和机制

游戏初始化和人数检测

当玩家进入地图后，初始化流程会自动触发。
触发条件是地图加载完成，且所有 function moment 循环命令方块开始正常运行。
在此期间，地图会做以下几件事：

  • 修改游戏规则；
  • 创建地图所需的积分板（scoreboard）；
  • 持续检测当前玩家人数，并循环执行 function func/Player/JoinWorld 指令。

如果只有一名玩家在线，地图会显示提示：“等待其他玩家加入…”。
一旦第二名玩家加入，提示自动消失，游戏时间被设为 330 秒，并立即启动 30 秒 的倒计时。右侧的公告栏也会同步刷新倒计时数字，这部分由 function second 驱动。

至于具体的指令细节，这里不再展开，因为对后续改图并无实际帮助。你只需要记住一个核心数字——330和300.

倒计时归零的瞬间，系统会执行 function func/GameOn，正式拉开游戏序幕

游戏启动与身份分配

首先，每位玩家都会获得一套初始装备（防具、基础武器等），确保开局公平。
紧接着，便是整张地图最核心的环节——身份分配。
流程如下：

  1. 全员设为平民
    系统先将所有玩家在身份积分板（identity）上的分数统一设为 1，即默认平民身份。
  2. 随机抽取神职与狼人
    根据当前在线玩家人数，按既定比例（例如每 2 人产生 1 狼人，每 3 人产生 1 神职）随机抽取若干名玩家。
    抽取方式依赖选择器 @r，配合条件判断，将选中玩家的 identity 分数从 1 修改为对应数值（如神职为 3，狼人为 13），从而实现身份切换。
  3. 身份提示与技能发放
    · 使用 title 指令向每位玩家清晰显示其所属身份（例如“你是平民”、“你是狼人”）。
    · 同时，利用 give 指令为不同身份发放专属技能道具和装备，比如狼人的“秒杀刀”、神职的“技能”等

游戏过程

游戏正式启动后，玩家们将进入对抗阶段。整局游戏时长为 300 秒，从倒计时结束那一刻开始计时。
①淘汰与提示
当任意玩家被击杀，系统会通过 title 和 say 指令向全服发送公告，明确提示“XX 被淘汰，身份确认为 XXX”，让所有人实时掌握场上局势。

②身份技能触发
每位玩家的身份技能，均由其 identity 积分板数值驱动。系统会持续检测该积分板，并根据数值自动执行对应的技能函数（function），例如狼人的夜袭、神职的探测等。

③道德值（Moral）系统

  • 为了防止误伤队友，地图内置了 道德值 机制。当玩家攻击时，系统会检测攻击者与被攻击者所属阵营：
  • 若攻击者击中 同阵营 玩家（例如平民打了平民），则会扣除该攻击者的道德值。
  • 若攻击者击中 不同阵营 玩家（例如狼人打了好人），则会增加道德值。
  • 当某玩家的道德值降至 0 时，该玩家将被“禁赛”——即暂时无法继续参与本局游戏（通常会被强制旁观或传送出场地）。
  • 实现原理：系统通过检测附近玩家被谁淘汰，并结合身份积分板判断阵营归属，从而进行加减分操作。

④天黑机制（第 100 秒触发）

  • 游戏进行到 第 100 秒 时，命令方块矿车会根据积分板 show 中的虚拟分数，触发 “天黑” 效果。
  • 此时，狼人的身份暴露规则发生变化：系统会将狼人玩家的 bright 积分板值设为 1，这代表着他们的身份显示颜色发生变化（例如好人阵营显示绿色，预言家显示蓝色，而狼人则会变为红色），从而让其他玩家更容易辨识。

胜负判定

游戏会在任意时刻检测存活玩家情况，一旦满足以下任一条件，立即判定胜负：

  • 好人胜利：当场上 没有存活狼人 且 至少有一名好人（平民或神职）存活时，触发 function func/Hwin。
  • 狼人胜利：当场上 没有存活好人 且 至少有一名狼人 存活时，触发 function func/Twin。

判定结束后，系统会自动执行 function func/GameOver 来收尾，包括显示胜利信息、结算奖励等。

游戏结束与重置

无论是好人胜利还是狼人胜利，届时也会触发结束逻辑执行function func/GameOver，游戏都会进入重置阶段。

重置后，所有状态被清空，积分板归零，地图回到初始等待状态，并自动开始新一轮的等待和匹配——只要房间内仍有玩家，循环便会一直持续下去，实现“到头再来，循环往复”的设计.

正文

我们已经初步了解了地图运行的机制与逻辑，接下来就要着手解决具体问题了。

问题一：如何实现“诸神黄昏”模式？身份系统又该如何添加？

首先需要明确：决定玩家身份的积分板为 identity。在狼人行动3版本中，游戏内置的身份仅有预言家、女巫和猎人[在狼人行动6中，还会额外包含定序王子与蚀时狼妃]

根据游戏机制，身份分配是在游戏时间第300秒时进行的，会先将所有人设为平民，再从中随机抽取神职和狼人。那么我们有这样一个思路：检测到游戏时间为300秒时，将所有平民玩家的 identity 积分板改成对应身份数值，其中狼人的 identity 范围设定在11至13，这些为普通狼人，13以上的数值则作为狼人神职。

原作者其实已经预先做好了其他隐藏身份的数据，但并未在实际游戏对局中启用。现在我们需要自行补充这些身份.
